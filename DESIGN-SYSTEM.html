The Abstract admin design system

Every token, component, and rule the Abstract (MSP) admin portal is built from — pulled straight from the shipped screens so the code you write matches what's already there. Tailwind utility classes are the API; this page is the contract.

Tailwind CSS (CDN + inline config) Inter · Font Awesome 6 Desktop-first, responsive Light UI
Start here

How to consume this system

The portal has no build step — every screen is a standalone HTML file that loads Tailwind from the CDN and applies one inline config. Drop this exact <head> block into any new screen and you inherit the whole system: fonts, brand palette, and utility API. Everything after this section is how you use it.

<!-- Fonts + icons --> <link href="https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600;700;800&display=swap" rel="stylesheet"> <script src="https://cdn.tailwindcss.com"></script> <link rel="stylesheet" href=".../font-awesome/6.5.2/css/all.min.css"> <!-- Brand tokens: the one config every screen shares --> <script> tailwind.config = { theme:{ extend:{ fontFamily:{ inter:['Inter','sans-serif'] }, colors:{ navy:{ DEFAULT:'#172554', 50:'#EEF1FB', 100:'#D4DCF5', 200:'#A9B9EB', 300:'#7E96E1', 400:'#5373D7', 500:'#2850CD', 600:'#1D3FA4', 700:'#162F7B', 800:'#0F1F52', 900:'#172554' }, brand:{ blue:'#1D4ED8', purple:'#5B2E91', navy:'#172554' } } }}} </script> <body class="font-inter bg-slate-100"> <!-- page ground is always slate-100 -->
Neutrals are Tailwind slate, not gray. The system is built on the slate ramp (a cool, faintly navy-biased grey that sits under the brand). Reaching for gray-* or zinc-* will drift off-system — always use slate-*.

Radius & elevation

Corners scale with the element's weight: controls are soft, cards are softer, containers softest, and anything pill-shaped is fully round. Shadows are whisper-light — the system separates surfaces with borders, not drop shadows, reserving real elevation for overlays.

Elevation rule: cards use shadow-sm + a border border-slate-200. Only floating overlays (modals, popovers) earn shadow-2xl. No mid-tier drop shadows on in-flow content.

Iconography

Font Awesome 6 — fa-solid for actions and status, fa-regular for passive/nav accents. Icons are sized in text units and inherit the surrounding text color; inside pills they drop to 9–10px. One icon per control, always paired with a label except on the icon-button.

Components

Buttons

One primary per view — the gradient. Everything else is quiet: a filled slate secondary, a bordered ghost, a text-only danger, and the square icon-button for toolbar actions. Labels are verbs that name the outcome (“Run Report”, “Approve Agency”), never “OK/Submit”.

Primary class="... text-white rounded-lg px-4 py-2 text-xs font-semibold" style="background:linear-gradient(135deg,#1D4ED8,#5B2E91)" Secondary class="bg-slate-100 hover:bg-slate-200 text-slate-700 rounded-lg px-3 py-2 text-xs font-semibold" Ghost class="bg-slate-50 border border-slate-200 text-slate-700 hover:border-blue-300 hover:text-blue-600 rounded-lg px-3 py-2 text-xs font-semibold" Danger class="text-red-600 hover:text-red-700 hover:bg-red-50 rounded-lg px-2 py-1 text-xs font-semibold" Icon class="w-9 h-9 rounded-lg bg-slate-50 border border-slate-200 hover:border-blue-300" + aria-label
Every icon-only control needs an aria-label naming the action. The gradient primary is the only filled-color button — a second gradient button on one screen breaks the hierarchy.

Source badges — domain-specific

Booking source is the portal's core concept, so it gets its own reserved color pair, distinct from every status color. indigo = filled from Abstract's own pool; teal = filled by an agency. These two colors mean only source, everywhere: badges, bars, donut arcs.

Abstract-sourced Agency-sourced
Abstract class="... bg-indigo-50 text-indigo-700 border-indigo-200" icon: fa-building-shield Agency class="... bg-teal-50 text-teal-700 border-teal-200" icon: fa-handshake-angle
Data-visibility rule baked into color: source is never shown to the client. Any component that renders a source badge is Abstract-only (or agency-only for its own rows). See Rules.

Forms & filters

Inputs sit on slate-50 with a slate-200 border; on focus they turn white with a soft blue ring. Filter bars are a wrapped flex row of these fields, each led by an icon. The most important filter (Client / Agency) gets a stronger colored border to draw the eye.

Governance

Rules & accessibility

The system encodes business rules, not just looks. These are non-negotiable — a component that breaks one is wrong even if it renders perfectly.

Always

  • Use a canonical status string + its meaning color.
  • Right-align & tabular-align money and hours.
  • Give every icon-only button an aria-label.
  • Keep a visible :focus-visible ring on interactive elements.
  • Scroll wide content inside overflow-x-auto, not the page.
  • Show booking source only on Abstract (and agency-own) surfaces.

Never

  • Invent a status string or use a forbidden term.
  • Show pay/margin to a client, or charge to an agency.
  • Show booking source to a client, anywhere.
  • Set “Partially Filled / Filled” manually — it's derived.
  • Use gray-*; add a second gradient button; drop-shadow in-flow cards.
  • Convey state by color alone — pair it with text/icon.
Contrast & motion: body text is slate-600+ on white (≥ 4.5:1); pill text uses the 700 shade on the 50 tint (checked). Respect prefers-reduced-motion — transitions are decorative only. Target size ≥ 36px for touch controls.

Handover checklist

What to wire up so a new screen is on-system from the first commit.

  • Head block — copy the fonts + tailwind.config from Overview verbatim; body is font-inter bg-slate-100 overflow-hidden.
  • Shell — reuse the sidebar + header; set the active nav item to the gradient chip.
  • Tokens only — brand/navy/slate + the six semantic families; no ad-hoc hexes, no gray.
  • Status & source — pills from the vocabulary tables; source badges Abstract-only.
  • Primary action — exactly one gradient button; the rest secondary/ghost.
  • A11y pass — labels on icon buttons, focus rings, contrast, reduced-motion.
